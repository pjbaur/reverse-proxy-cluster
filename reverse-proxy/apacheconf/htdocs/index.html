reverse-proxy-cluster

Apache httpd reverse proxy running. Backends are enabled with Compose profiles — a route below only answers once its profile is up:

  • GET /java/messages — Spring Boot 3.5 / Java 21 (--profile java)
  • GET /nginx/ and GET /nginx/messages — static nginx (--profile nginx)
  • GET /node/messages — Node.js (--profile node)
  • GET /python/messages — Python (--profile python)
  • GET /balanced/messages — load-balanced across 3 node replicas (--profile balanced)
  • GET /failover/messages — hot standby: primary serves, standby takes over when it stops (--profile failover)
  • GET /sticky/messages — session affinity: one member per client cookie, round-robin without (--profile sticky)
  • GET /busy/messages?delay=ms — bybusyness: the member with fewest active requests answers; a long request is skipped around (--profile busy)
  • GET /stickyfailover/messages and GET /stickyfailover-strict/messages — sticky hot standby: a pinned session fails over to the standby and stays there; the strict route (nofailover=On) breaks with 503 instead (--profile stickyfailover)
  • GET /mixed/messages — mixed-stack round-robin: one node and one python member alternate per request (--profile mixed)
  • GET /balancer-manager — balancer dashboard (private ranges only, --profile balanced)

Also served: this page over HTTPS at https://localhost:8443/ (self-signed dev cert) and GET /server-status (private ranges only).
